## Team Agreements (Gate 1 & Gate 2)

### Agreement 1: Directory Structure
- All group files reside inside `group12/`.
- Operators: `group12/operators/<op>.mlir` (all 32 banks, 16-bit).
- Traces: `group12/mappings/<target>/<op>/<optipim|heuristic>.trace`.
- Evaluation results: `group12/results/` (`results.csv`, `sim_check.csv`, `solve_times.csv`, `plots/`).
- Shared analysis & plotting: `group12/analysis/` (`score_traces.py`, `plot_results.py`, `parse_mapping.py`, `rerun.sh`).

### Agreement 2: Trace Format & Dilation/Stride Convention
- Loop bounds: Bound lines store loop split factors in order Level 2 (banks), Level 0 (time, marked with tag `T`), Level 1 (columns).
- Stride/Dilation order: `pim-opt` writes `DilationStride: dilation,dilation,stride,stride`, whereas the authors' baseline traces and `get_trace_perf.py` read `stride,stride,dilation,dilation`.
- All scorers (`group12/scripts/evaluate.py`, `group12/scripts/score_analytical.py`, `group12/analysis/score_traces.py`) handle this automatically: `optipim` traces are read dilation-first, while `heuristic` traces are read stride-first.

### Agreement 3: `results.csv` Schema & Cost Decomposition (Task 3.2)
Generated by `python3 group12/scripts/evaluate.py` -> `group12/results/results.csv`.
Columns:
1. `operator`: Operator ID (`C1`, `C2`, `C3`, `M1`, `M2`).
2. `target`: Architecture target (`hbmpim`, `simdram`).
3. `mapper`: Mapping method (`optipim`, `heuristic`).
4. `banks`: Number of active banks (product of Level 2 loop factors).
5. `precision`: Bit-width (16 for all benchmark operators).
6. `analytical_cycles`: Total cycles predicted by the authors' Python analytical model (`finalPerformance`).
7. `simulated_cycles`: Cycles reported by Ramulator2 simulation (from `sim_check.csv`).
8. `compute`: Arithmetic / activation cycle cost.
9. `input_loading`: Input activation loading cycle cost.
10. `weight_loading`: Filter/weight loading cycle cost (HBM-PIM only).
11. `output`: Output transmission cycle cost (SIMDRAM only).
12. `solve_seconds`: Gurobi ILP solver execution time in seconds (for `optipim`).

#### Analytical Cost Mapping (`validation/analytical_modeling/analytical.py`):
- **SIMDRAM (Bit-serial DRAM PIM, device type 0)**:
  - `compute`: Bit-serial multiplication and reduction addition latency:
    $$\text{compute} = \text{numMulCol} \times \text{mulLat} + \text{numRedCol} \times \text{addLat} = \text{cost} - \text{inLoadingCost} - \text{outTransCost}$$
  - `input_loading`: `inLoadingCost` (streaming input activations from external controller into DRAM rows).
  - `weight_loading`: $0.0$ (weights remain stationary inside DRAM bitlines).
  - `output`: `outTransCost` (transmitting final outputs out of DRAM subarray).
  - Total: $\text{analytical\_cycles} = \text{compute} + \text{input\_loading} + \text{output}$.

- **HBM-PIM (Near-Bank SIMD PIM, device type 1)**:
  - `compute`: Row activation latency for DRAM row buffers:
    $$\text{compute} = \text{num\_mul\_col} \times \text{rowActLat} = \text{cost} - \text{inLoadingCost} - \text{numFilPELoading}$$
  - `input_loading`: `inLoadingCost` (streaming activations through channel DQ pins across pseudo-channels).
  - `weight_loading`: `numFilPELoading` (loading filter/matrix weights into bank PE registers).
  - `output`: $0.0$ (output write-back is negligible / not counted in the model).
  - Total: $\text{analytical\_cycles} = \text{compute} + \text{input\_loading} + \text{weight\_loading}$.
# Group 12: OptiPIM reproduction

This folder holds everything Group 12 adds on top of the authors' OptiPIM repo
(ETHZ-DYNAMO/OptiPIM). We do not edit the authors' files; all our scripts,
inputs and results live under `group12/`.

**Goal:** reproduce OptiPIM (ISCA 2025) at reduced scale. We compare optimal ILP
mappings with the weight-parallel heuristic for 2D convolution and matrix
multiply on HBM-PIM and SIMDRAM, check the analytical cost model against the
simulator, and add one improvement of our own.

**Left out (course scope):** real hardware, the PIM-DL genetic baseline, full
networks, and the memory scalability study.

## Agreement 2: mapping file format

Both mappers write the authors' trace format, which the analytical model and
the simulator already read. Example: the heuristic mapping for C1, taken from
`baseline_mappings/heuristic_1/hbm_baseline/257-32_banks-ResNet50-12/0.trace`.

```
conv2d
Problem: 1,128,28,28,128,3,3
DilationStride: 2,2,1,1
Loop: N,K,P,Q,C,R,S,N,K,P,Q,C,R,S,N,K,P,Q,C,R,S
Bound: 1,32,1,1,1,1,1,1,1,1,7,128,3,3,1,4,28,4,1,1,1
Tag: P,P,P,P,P,P,P,T,T,T,T,T,T,T,P,P,P,P,P,P,P
StartBankRow: 0,0
Coeff_N2,N0,N1: 1,1,1
Coeff_K2,K0,K1: 4,1,1
Coeff_P2,P0,P1: 28,1,1
Coeff_Q2,Q0,Q1: 28,1,7
Coeff_C2,C0,C1: 128,1,128
Coeff_R2,R0,R1: 3,1,3
Coeff_S2,S0,S1: 3,1,3
end
```

- `Problem` lists the layer sizes in the order N,K,P,Q,C,R,S for conv2d.
  For matmul the first line is `gemm` and there are 5 loops: N,K,P,Q,R.
- `Bound` holds three groups, each in loop order: level 2 (banks), then
  level 0 (time, tag `T`), then level 1 (columns). For every loop, the three
  numbers multiply to the full size.
- `Coeff_X2,X0,X1` gives how the indices of loop X are numbered (the paper's
  flexible indexing).
- A new mapper is correct only if its file scores without errors in
  `validation/analytical_modeling/get_trace_perf.py`.

## How to run

Full build steps (packages, Gurobi licence, environment variables) are in the
authors' top-level README. In short, on Linux (WSL2 or a Linux server):

```
make python_env && source optipim_env/bin/activate
make compile_optipim                                    # hours, once
make test                                               # smoke test

# one operator on one target
bash group12/scripts/run_optipim.sh C1 hbmpim

# all OptiPIM mappings
for OP in C1 C2 C3 M1 M2; do
  for T in hbmpim simdram; do bash group12/scripts/run_optipim.sh $OP $T; done
done
```

The heuristic and the evaluation scripts are plain Python and run on any
laptop with the venv active. Their usage goes here once they exist.
